# easy text

**easy text** 是使用 Electron 与 CodeMirror 6 独立实现的本地代码编辑器，标识为 **ET**。桌面版可以直接打开、编辑和保存磁盘文件；浏览器版用于无需安装的编辑体验，保存通过下载完成。

源码仓库：[fishman-r/easy-text](https://github.com/fishman-r/easy-text)。应用使用独立实现，不包含 Sublime Text 私有实现或品牌素材，也不声称与 Sublime 全功能等价。

## 0.5.0 增量

新增全部保存、恢复关闭标签（含跨重启未保存缓冲区）、导航前进、全选相同文本、选区撤销/重做、合并行、倒转行、首字母大写、交换大小写及 ROT13。设置表单新增行号、空白字符、活动行高亮及 80/100/120 列标尺。修复缩进转换按当前 Tab 宽度计算、关闭非活动分栏标签、书签随编辑映射及启动恢复覆盖早期输入的问题。

[功能对照表](FEATURE-COVERAGE.md) 区分已实现、部分实现和缺失；[安装版验收记录](ACCEPTANCE-0.5.md) 列出实际操作和局限。完整 Sublime 插件、语法/主题格式、多窗口/网格和多根项目仍未完成。

## 启动与打包

建议使用 Node.js 22 或更新的受支持 LTS。首次安装依赖：

```sh
git clone git@github.com:fishman-r/easy-text.git
cd easy-text
npm ci
```

启动桌面编辑器：

```sh
npm run desktop
```

启动浏览器开发版本：

```sh
npm run dev -- --port 5173
```

打开终端显示的本地地址。浏览器版不能直接写回原文件、访问 Git 或执行本机程序；这些入口会明确提示需要桌面版。

生成 macOS Apple Silicon 应用：

```sh
npm run package:mac
```

产物为 `dist-desktop/easy text-darwin-arm64/easy text.app`。应用尚未签名、公证，没有自动更新服务。打包目标明确为 ARM64；开发 Electron 的架构取决于运行 npm 的 Node 架构，不能用开发窗口启动成功代替最终 `.app` 的验证。

## 使用方式

桌面版通过系统菜单提供文件、编辑、选择、查找、视图、前往、工具和项目操作；浏览器版保留紧凑菜单。左侧为“已打开文件”和“文件夹”，顶部为文件标签，右侧为文档概览，底部为状态栏。项目搜索、大纲、Git 和构建可从菜单或命令面板打开。

- **打开文件 / 文件夹**：桌面版通过原生选择器授权后访问文件。目录列表按需读取文件内容，不会执行项目代码。
- **保存 / 另存为**：桌面版检查磁盘版本后写入；检测到外部修改时拒绝覆盖。浏览器版发起下载，因无法确认实际落盘而保留修改标记。
- **分栏**：每栏顶部可独立选择文档。同一文件的两栏共享文本变更，同时保留和映射选区。窄窗口上下排列。
- **项目替换**：先查找或预览，再明确应用。桌面版还会原生确认；应用后提供最近一次替换的撤销入口。未保存的相关缓冲区会阻止替换。
- **Git / 构建**：先打开桌面项目。Git 支持状态、差异、日志、暂存当前文件和提交已暂存内容。构建选择可执行程序并逐项添加参数，例如 `npm` 配合两行参数 `run`、`build`，确认后启动并展示输出。

## 界面语言

0.4.0 内置简体中文语言包，默认启用。中文覆盖原生菜单、侧栏、状态栏、查找/替换、折叠和补全提示，以及应用自己的文件、插件和构建确认框。界面语言不改变文件内容、代码标识、文件名、编码或快捷键。

通过 **偏好设置 → 界面语言…** 或命令面板的“界面语言 / 简体中文语言包”选择“简体中文”或“跟随系统”。设置保存后重启仍有效；未支持的系统语言回退为简体中文。

语言资源位于 `src/locales/zh-CN.json`，桌面菜单和编辑区共用同一份资源。`en.json` 仅用于内部缺键回退，不作为尚未完整翻译的英语界面选项。第三方插件原始错误、Git 和构建程序输出保留原文，便于诊断。

## Python 插件

桌面版从 **工具 → Python 插件…** 打开插件管理，可选择 Packages 目录、`.sublime-package` 或单个 `.py`。确认信任后启动独立 Python 进程，加载已注册命令；可在命令面板搜索插件命令，也可在管理面板查看错误、禁用或移除登记。应用重启后需要明确启动宿主。

需要 Python 3.9 或更新版本；可通过环境变量 `EASY_TEXT_PYTHON` 指定解释器绝对路径。Python 版本不会自动模拟 Sublime 自带的 Python 环境，旧插件的语法、依赖及原生模块仍可能不兼容。

插件以当前用户权限运行，能够访问文件和网络。独立进程提供故障隔离和超时终止，不是安全沙箱。安装入口不会自动读取或执行已有 Sublime Packages。请选择可信的插件源。

兼容层独立实现 `sublime` / `sublime_plugin` 的命令、部分视图/选区/设置及事件接口，未实现的接口明确报错。宿主使用 Unicode 码点，编辑器桥使用 UTF-16，结果带文档版本校验。具体支持与限制见 [桌面说明](desktop-notes.md)。

| 当前文档查找与替换 | Mod F |

## 数据与执行边界

编辑文本在内存中统一为 LF；保存时按文件元数据恢复换行、编码和 BOM。成功写入才更新保存基线。已打开的未保存内容不会因为再次打开文件或异步项目替换返回而被静默覆盖；发生冲突时需要另存为或明确重新读取磁盘。

原生保存采用版本检查、临时文件、fsync 和原子重命名，并保留接受保存前的原字节备份。不过这不是跨进程的原子比较交换；不能保证挡住所有外部写入竞态。备份位于应用数据目录，目前没有备份浏览器或自动清理策略。

项目替换逐文件保存，不是跨文件事务。后续文件失败时可能部分完成，会报告错误；成功的文件仍保留备份。替换撤销在当前应用进程内有效，并检查应用后的文件版本。重启后不能使用旧撤销 ID，旧字节备份仍保留。

构建不会在打开项目时自动执行。界面使用可执行程序和参数数组，默认不经过 shell；用户明确指定 shell 程序仍会执行相应代码。构建程序拥有当前用户的操作系统权限，不是沙箱中的代码执行。应用本身不实现自动推送、后台提交或项目联网行为。

## 实际限制

- **仅支持 Sublime Python API 的已实现子集，不保证任意插件兼容。** 不支持 Package Control、原生扩展 ABI、完整语法包与主题引擎，也不保证全部命令或快捷键等价。
- 没有全语言 LSP、类型检查、跨项目语义索引、查找所有引用、智能重构、调试器或交互式终端。
- JS/TS 导航使用当前文档解析树和语法作用域选择候选，不提供完整 JavaScript/TypeScript 语义。对象成员和跨文件引用不保证解析；其他语言大纲使用声明模式扫描。
- 没有 GPU 渲染或超大工程性能等价承诺。桌面单文件上限 10 MiB、目录清单上限 12,000 项；浏览器导入单文件上限 5 MiB。
- 项目搜索最多返回 1,000 处结果；替换预览有 200 文件 / 20 MiB 上限。搜索可能跳过不支持或无法读取的文件，不能把返回结果视为无限范围完整索引。
- 桌面正则匹配使用独立线程、单文件超时；浏览器项目正则使用 Web Worker 和 2 秒总超时。超时会停止该操作。
- 差异面板仅比较前 5,000 行；文档概览对长文件采样绘制，不复制 Sublime 的渲染方式。
- 不猜测 GBK 等旧编码或无 BOM 的 UTF-16。混合换行不会被无提示地规范化。
- 会话和宏配置保留在本机，没有账户、云同步或多人协作。突然掉电/崩溃仍可能丢失尚未提交保存的变更。

## 可视化设置

通过 `⌘,` 或“偏好设置 → 设置”打开统一设置面板。主题、字号、缩进、换行显示、文档概览和编辑布局均通过控件调整；语言、快捷键、代码片段、构建、插件和文件格式也有对应表单。代码片段正文仍是代码输入框，构建参数逐行编辑，均无需编写 JSON。

应用内弹窗统一使用 12px 圆角边框，菜单和表单控件使用 6px 圆角；确认框支持取消、Esc 和关闭按钮，取消不会执行操作。系统打开／保存文件选择器沿用 macOS 原生样式。
